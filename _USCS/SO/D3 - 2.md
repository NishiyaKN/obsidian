# 📚 Gerenciamento de Processos em Sistemas Operacionais

## 🌟 Visão Geral
O material aborda os conceitos fundamentais do gerenciamento de processos em sistemas operacionais, focando nos contextos de hardware e software, estados de processos, escalonamento da CPU e troca de contexto. O objetivo é entender como o SO gerencia a execução de processos para otimizar o uso dos recursos computacionais.

---

## 🖥️ Contexto de Hardware
Refere-se às informações armazenadas no Bloco de Controle de Processo (BCP) necessárias para retomar a execução de um processo após uma troca de contexto. Inclui:

- **Registradores da CPU**:
  - **Contador de Programa (PC)**: Endereço da próxima instrução a ser executada.
  - **Registradores Gerais**: Armazenam valores temporários e resultados intermediários.
  - **Ponteiro de Pilha (SP)**: Aponta para o topo da pilha do processo.
  - **Registrador de Status**: Flags que indicam o resultado de operações anteriores (ex.: carry, zero).
  - **Registradores de Ponto Flutuante** (se aplicável).

### 🔄 Troca de Contexto
Quando um processo perde a CPU, seu contexto de hardware é salvo no BCP. O SO então carrega o contexto do próximo processo a ser executado.  
Exemplo de fluxo:  
`Processo 0 (executando) → Salva registradores → Carrega registradores do Processo 1 → Processo 1 (executando)`.

---

## 💻 Contexto de Software
Conjunto de informações mantidas pelo SO para gerenciamento do processo, não diretamente relacionadas ao hardware. Inclui:

- **Identificador Único (PID)**: Número ou nome que referencia o processo.
- **Tabela de Arquivos Abertos**: Recursos em uso pelo processo.
- **Variáveis de Ambiente**: Configurações específicas do processo.
- **Prioridade de Execução**: Define a ordem de acesso à CPU.
- **Cotas (Limites)**:
  - Número máximo de arquivos abertos.
  - Tamanho máximo de memória alocável.
  - Número máximo de subprocessos.

---

## 🔄 Estados de Processos e Transições
Os processos podem estar em um dos seguintes estados, com transições definidas por eventos:
```
novo → admissão → pronto → escalonamento → execução → término
↑                       ↓
└─ espera (evento/E/S) ─┘
```
- **Pronto**: Processo aguardando alocação da CPU.
- **Execução**: Processo em execução na CPU.
- **Espera**: Processo bloqueado (ex.: aguardando E/S).

---

## ⏳ Escalonamento da CPU
O SO decide a ordem de execução dos processos para otimizar recursos. Principais critérios:

| Critério            | Descrição                                                             |
| ------------------- | --------------------------------------------------------------------- |
| **FCFS**            | First Come, First Served: executa na ordem de chegada.                |
| **SJF**             | Shortest Job First: prioriza processos com menor tempo de execução.   |
| **Por Prioridades** | Processos com maior prioridade são executados primeiro.               |
| **Round-Robin**     | Cada processo recebe um "quantum" de tempo antes de ser preemptado.   |
| **Múltiplas Filas** | Filas separadas para categorias de processos (ex.: sistema, usuário). |

### 🔄 Preempção
Interrupção de um processo em execução para alocar a CPU a outro processo, comum em sistemas multitarefa. Envolve:  
- Mudança de modo (usuário → supervisor).  
- Salvamento do estado atual.  
- Seleção e carregamento do novo processo.  

**Overhead**: Custo adicional de recursos (tempo/memória) para realizar a troca de contexto.

---

## 📌 Conclusão
O gerenciamento de processos é essencial para a eficiência do SO, envolvendo:  
1. Salvamento e restauração de contextos (hardware/software).  
2. Transições entre estados (pronto, execução, espera).  
3. Escalonamento justo e eficiente da CPU.  
4. Minimização de overhead durante trocas de contexto.  

Entender esses conceitos é fundamental para projetar e otimizar sistemas operacionais robustos e responsivos.
