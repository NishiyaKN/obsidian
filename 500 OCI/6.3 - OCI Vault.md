- Used to centrally manage encryption keys and secret credential
	- **Encryption keys**: used to encrypt and decript data
	- **Secrets**: passwords, certificates, ssh-keys, auth tokens, etc
- Supports AES, RSA and ECDSA
- Regional service with public API endpoint
## Protection Modes for Keys
### Software
- Stored in a server
- Can be exported from server
	- Can perform cryptographic operations on the client instead of the server
### Hardware Security Modules
- All cryptographic operations involving the key happen only in the HSM
- Physical computing device
	- Tamper-evident hardware
	- Used to manage ditial keys
	- Performs cryptographic functions
## Envelop Encryption
- Basically a two tiered hierarchy for keys (the way Vault operates)
	- Data Encryption Keys: used to encrypt user data
	- Master Encryption Keys: encrypt the data key
- Can rotate master key
- Vault is lost if master key is deleted
	- Vault can't be deleted immediatly, takes from 7 to 30 days
## Encryption
- Used to transform plain text into cipher text
	- Randomized letters and numbers
- **Key**: string stored in a file that encrypt or decrypt data
- **Symmetric Encryption**: uses a single key to encrypt and decrypt
	- Cannot be used for digital signing
	- AES is an example
- **Asymmetric Encryption**: uses a public key and private key
	- Anyone can encrypt text with the public key
	- Only the holder of the private key can decrypt 
	- RSA is an example
- **ECDSA**: only used for digital signing, can't encrypt nor decrypt
