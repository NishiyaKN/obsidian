- Uses NFS
- **Shared between multiple compute instances**
	- Can access from outside the VCN (Fastconnect, IPSec, etc)
- Hierarchical collection of documents
	- Organized into directories
- To access the FS, you need to associate the FS with the mount target by creating an export
## Characteristics
- Replicated in multiple ADs
- Up to 8 exabyte
- Can make snapshots (up to 10,000)
- Don't partition disk, just mount the filesystem
## Concepts
### Mount Target
- NFS endpoint
- Lives in a subnet
- Used by the client to connect to the FS
- Has an IP address/DNS name
- Same mount target can be reused for multiple FS
### Export
- Controls how NFS clients access FS when they connect to a mount target
- **Export Set:** collection of one or more exports
#### NFS Export Options
- Set of parameters that specify the level of access granted to NFS clients
	- Enable more granular access control
- Can specify access levels for IP or CIDR blocks
	- Set:
		- Source IP
		- Ports (can use privileged ports, that only root user can open)
		- Access type (read only or read/write)
- Applies the first set of options that matches the source IP, ignores the rest

### Paths
- **Export Path**: uniquely identifies the file system within the mount target
	- Can't be edited after created
	- Can associate up to 100 file systems to a single mount target
	- Used by the instance to mount the file system
- **Mount Point Paths:** path inside the client where the FS is mounted
	- Ex: `sudo mount 10.0.0.6:/FS1 /mnt/mountpointA`
	- `mountpointA` is the mount path
- **FS Paths:** path to directories within the FS 
	- Contains the contents of the FS
## Usage and Metering
- Updates hourly
- Can use `df` to accurately view the file system dize
	- `du` may report a larger size
- Snapshots only use space equivalent to modifications
- Clones use space of it's metadata (don't duplicate the snapshot) and incremental changes
