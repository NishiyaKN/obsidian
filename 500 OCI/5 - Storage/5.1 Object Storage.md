- Storage for the web, such as images, videos, etc
	- Ideal for unstrucutred or semi-structured data
- Unlimited capacity 
- Regional service
- Accessed with via API with simple HTTP commands like Put and Get
- **Data encryption by default, cannot be turned off**
## Resources
- **Namespace:** top-level container for all buckes, globally unique name
- **Bucket:** container for storing objects
	- Needs to be unique in a region in a tenancy
	- Flat hierarchy (can simulate folder structure via prefixes, )
- **Object**: the thing to be stored + it's metadata
	- Can be up to 10TiB
	- Cannot be edited, only replaced

## Multipart Uploads
- Upload data in parallel
	- Recommended for files over 100MiB
- Can be divided into up to 10,000 parts
	- Each part must be at least 10 MiB
	- Upper limit for a part is 50Gib
- Retry uplod of object parts and not the entire object
- Can pause uploads of individual partsand resume later
### How it works
1. Split data into parts (if using CLI them only specify the part size)
2. Initiate an upload using 1 API call
	1. An upload ID is provided
3. Upload parts (1 API call for each part)
4. Commit upload (object is reconstructred in the object storage)
## Copy Object
- Can only copy to already existing buckets
- ETag of object changes in the destination
	- ETag is a id for a version of a resource
## Logging
- Sends read and write access events to OCI Logging service
- Open source Fluentd format
- Enable at bucket level
- Logs GET, LIST, HEAD for read log, PUT, POST, DELETE for write log
