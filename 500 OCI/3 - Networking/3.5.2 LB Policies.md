- Determines how to distribute traffic between the BE
- Apply differently to TCP Load Balancer, sticky HTTP and non-sticky HTTP
## Policy Types
### Round Robin
- Default
- Incoming traffic is distributed sequentially to each server
- Works best when
	- BE have similar capacity
	- Load required by each request does not vary signifcantly
### Least Connection
- Send to the BE with the fewest active connections
### IP Hash
- The incoming IP is used as a hashing key
- Routes non-sticky traffic to the same BE
	- Requests from the same client will go to the same BE
## Request Type
### TCP LB
- Policy and weight will be used to direct an initial incoming request
	- Subsequent packets will be sent to the same endpoint (BE)
- A client will send data to the same BE
### HTTP Request (sticky)
- Forwards the request to the BE that is specified by the cookie's session info
### HTTP Request (non-sticky)
- Policy and weight is applied to every incoming request
- A client can send requests to different BE
