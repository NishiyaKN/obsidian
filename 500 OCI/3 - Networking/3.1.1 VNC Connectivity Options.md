VCNs can talk to each other without peering through the Internet, each needing a public IP for the instances
## VCN to VCN - Peering
- Cannot have overlapping CIDRs
- VCNs can be from different tenancies
### Local Peering
- Communication between 2 VCNs in the **same region**
- VNC 1, peered to VCN 2, cannot connect to the internet via a IGW in the VCN 2, **==however==** it can receive traffic
#### Using LGP
- High b/w, low latency
1. Have 1 LGP in each VCN
2. Make a connection between the LGP
3. Configure Route Tables and Security Lists
#### Using upgraded DRG (v2) 
- High flexibility in routing
1. Create a single DRG in the region
2. Attach it to both VCNs
3. Configure Route Tables and Security Lists
### Remote Peering
- Communication between 2 VCNs in different regions (can be used for same region)
	- Legacy DRGs do not support cross tenancy connection
1. Create a DRG to each
2. Attach the DRGs to each VCNs
3. Create Remote Peering Connection on each DRG
4. Make a connection between each RPC
5. Configure Route Tables and Security Lists
##  VNC to on-premises
- **Public Internet:**
	- Uses IGW or NATGW
- **Site-to-Site VPN:**
	- Encrypted connection, IPSec VPN
	- Free
- **FastConnect:**
	- Dedicated connectivity
		- Low lantency and high bandwidth
	- Only charges the port hourly
# BGP
# Border Gateway Protocol
- Routing protocol fo the Internet
- Determines the best network routes
## AS - Autonomous System
- Collection of connected IP networks under control of a single administrative entity
	- ISP, corporations, universities, etc
### ASN - Autonomous System Number
- Unique ID assigned to each AS
#### BGP Peer
- Device that exchange routing information
	- Performs Route Discovery and Path Selection
