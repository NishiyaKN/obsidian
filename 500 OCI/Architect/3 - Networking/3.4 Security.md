Ways to secure the VCN:
- Separate public and private subnets
- Firewall rules on the instance
- IAM policies
- Route Tables
- Gateways
- Security Zones
	- Cannot have public subnet
- Security rules
	- Security Lists
	- Network Security Group
## Security Lists
- Basically firewall rules **associated to a subnet**
	- Applied to all instances inside the subnet
		- Up to 5 SL in a subnet
	- Every VCN comes with a SL by default
	- Stateful: If traffic is allowed in one direction, return traffic in the opposite direction is also allowed
		- Stateless is recommended for high volume internet facing website with HTTP/S
	- If it's a Ingress rule, defines the source CIDR
	- If it's a Egress rule, defines the destination CIDR

### Default Security List
- Does not include a rule to allow ping requests
- Allows SSH (22, TCP traffic) from autohorized source IP addresses
## Network Security Groups
- Similar to a Security List
- Used to control traffic flow between **specific resources within a VCN**
- Only apply to specific VNICs from the VCN
	- Basically firewall rule to instance level, allows for more fine grained control
- A VNIC can be added into up to 5 NSG 
- Can be used as source or destination in the rules
### Ingress Rule
- Defines what incoming traffic is allowed
- Need to specify
	- Source Type
		- CIDR block
		- Service
		- NSG
	- IP protocol
		- RDP
		- SSH
		- ICMP
	- Source Port Range (optional)
	- Destination Port Range (optional)
### Egress Rule
- Need to specify
	- Destination Type
		- Same as Source Type
	- Destination
	- Source Port Range (optional)
	- Destination Port Range (optional)
