## Workflow
![[Pasted image 20250824225532.png]]
1. Resources emmits metrics
2. Metric data is aggregated based on the functions
3. For each Metric, alarms are defined using a trigger rule condition
	1. Alarm query must specify a metric, statistic, interval and trigger rule
4. Integrate with the Notification service
## Alarm states
- **OK** - no issue
- **Firing** - sends notification, triggers automation task
- **Reset** - not detecting the metric firing 
- **Repeat** - when in a firing state, repeatedly sends notification

- **Supression:** avoid publishing alarm messages (pause)
## Best Practices
- Create a set of alarms for each metric based on resource behavior:
	- **At risk**: resources that can potentially fail if a threshold is surpassed
		- Ex: compute instance with over 80% CPU utilization
