## Identity Domain
- Container for managing users, groups and policies
	- For example: separate production team, development team
- ==To create domain, it needs to be contained in a Compartment, either Root or a new one==
- Each Identity Domain has a default administrator group and admin user
- The selected region in the console when creating a domain will become the domain's home region
	- Not replicated automatically to other regions
### Default Domain
- Auto created in the tenancy (root compartment)
- Auto replicated across all regions
### Default Groups
- Exists in every domain
- Cannot be deleted
- **All Domain Users** - contains all users
- **Administrators** - users with access to all OCI resources
## Principal
Identity of the caller trying to access or operate on a resource
- Users
- Groups
- Resource principal - resources that can make API calls to other OCI services
### Resource Principal Types
#### Infrastructure Principals
- Instances can perform actions on service resources
	- Ex: An application from an instance gets an object from object storage service
#### Stacked Principals
- Projecting one principal on top of another
	- A service controls a resource that specifies the intention of the resource
		- Database that makes a call to the object storage service to keep backups
#### Ephemeral Principals
- Temporary access to other services
	- Oracle Function
## Dynamic Groups
- Can group different resource principals together
- They are dynamic because we can set a rule to auto add/remove members

>`All | Any {instance.compartment.id = '<compartment-ocid>'}`
>	Adds all compute instances of a specified compartment to the group

>`All {instance.id = '<instance-ocid>'}
>	Adds a specific instance to the group

>`Any {resource.type = 'dbaas', resource.compartment.id='ocid'}
>	Adds the resource to the group
