### Basics
- **GitHub Actions** -> scripts to automate tasks
	- Three types:
	- **Container actions**: environment is part of the action's code (hosted Linux only)
		- Can be referenced on workflows from Docker Hub
	- **JavaScript actions**: no environment in the code, run on a VM (hosted or on-prem Linux, Windows, macOS)
	- **Composite actions**: combine multiple steps within one action
- **GitHub Actions Workflow** -> process inside repo to automate dev lifecycle task (build, test, deploy)
	- Crete by adding a yml file on `.github/workflows`
	- Needs to have at least 1 job (which is associated with a runner)

- **Workflow -> Jobs -> Steps -> Actions**
### Trigger methods
- `push`: when commits land on the repo
- `schedule - cron`: m h d m w
	- `*/5 * * * *` -> every 5 minutes (the shortest interval you can run)
- `workflow_dispatch` -> manual trigger using REST API or button
- `repository_dispatch` -> HTTP request to the repo 
	- Require PAT auth
	- JSON with:
		- `event_type`: (required) treated as the action or type of the dispatch
		- `client_payload`: (optional) object for custom data
- webhooks
### Conditionals
- Most need to use ${{ >expression< }} to work 
	- `if` doesn't
### API
**Trigger**: POST to `api.github.com/repos/{owner}/{repo}/dispatches` 
**Stop**: DELETE to `/repos/{owner}/{repo}/actions/runs/{run_id}`
### Specify a version
```yml
steps:    
  # Reference a specific commit
  - uses: actions/setup-node@c46424eee26de4078d34105d3de3cc4992202b1e
  # Reference the major version of a release
  - uses: actions/setup-node@v1
  # Reference a minor version of a release
  - uses: actions/setup-node@v1.2
  # Reference a branch
  - uses: actions/setup-node@main
```
