# 📝 Classificação e Paradigmas de Linguagens de Programação

**Visão Geral:** O documento explora a evolução e a categorização das linguagens de programação, dividindo-as por nível de abstração em relação ao hardware, por ordem cronológica (gerações) e por paradigmas. Compreender essas classificações é essencial para escolher o modelo interpretativo correto e a ferramenta ideal para solucionar diferentes tipos de problemas computacionais.

## 📏 Classificação por Nível
A proximidade da linguagem com o hardware define seu nível de abstração.

| Nível | Características | Exemplos | Prós / Contras |
| :--- | :--- | :--- | :--- |
| **Baixo Nível** | Voltadas para a máquina, manipulam diretamente instruções do processador e memória. | Assembly | ➕ Alta velocidade e eficiência de memória.<br>➖ Baixa portabilidade e difícil estruturação. |
| **Médio Nível** | Mesclam abstrações humanas com recursos de baixo nível (ex.: acesso a endereços de memória via ponteiros). | C | ➕ Poderosas e adequadas para software de alta performance.<br>➖ Sintaxe pode ser complexa e perigosa. |
| **Alto Nível** | Focadas no ser humano, ocultam o funcionamento interno do hardware e são independentes de arquitetura. | Java, C#, Lua | ➕ Alta portabilidade e produtividade na escrita.<br>➖ Geram executáveis mais genéricos, consumindo mais recursos. |

## ⏳ Classificação por Geração
A evolução histórica reflete a busca por linguagens mais produtivas e fáceis de usar.

* **1ª Geração (Máquina):** Código binário (`0`s e `1`s) compreendido diretamente pela CPU. Fortemente sujeito a erros.
* **2ª Geração (Assembly):** Uso de mnemônicos (abreviações como `add`, `mov`) para substituir o binário. Exige tradução.
* **3ª Geração (Usuário):** Linguagens estruturadas para domínios comerciais e científicos. Possuem controle de fluxo (loops, desvios). Ex: Pascal, BASIC, C.
* **4ª Geração (Aplicação):** Focadas em alta produtividade e domínios específicos. Exigem menos linhas de código para tarefas complexas. Ex: SQL, MATLAB.
* **5ª Geração (Conhecimento):** Focadas em Inteligência Artificial. Baseiam-se em restrições e regras lógicas em vez de algoritmos procedurais. Ex: Prolog.

## 🧠 Paradigmas de Programação
Um paradigma é um ponto de vista que determina como o programador modela e atua sobre uma realidade computacional.

| Paradigma                | Conceito Principal                                                                                                   | Vantagens                                                                            | Desvantagens                                                                 | Exemplos           |
| :----------------------- | :------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------- | :--------------------------------------------------------------------------- | :----------------- |
| **Imperativo**           | Foco no *estado* e nas *ações*. Instruções mudam os valores de variáveis passo a passo (Arquitetura de Von Neumann). | Eficiência e modelagem "natural" de fluxos do mundo real. É o paradigma dominante.   | Tende a gerar códigos confusos (dados misturados com comportamento).         | C, Pascal, Fortran |
| **Funcional**            | Avaliação de funções matemáticas. Elimina estados e variáveis mutáveis (estilo declarativo).                         | Facilita provas matemáticas e resolução de problemas de otimização.                  | Ineficiência de execução e dificuldade em manipular entrada/saída (E/S).     | Haskell, Lisp, ML  |
| **Lógico**               | Baseado em lógica formal. O programador declara *fatos* e *regras*; o computador deduz o resultado.                  | Alto nível de abstração, muito próximo ao raciocínio lógico humano.                  | Complexidade exponencial e dificuldade em expressar algoritmos tradicionais. | Prolog             |
| **Orientação a Objetos** | Estruturação em *classes* (moldes) que geram *objetos*. Une estado (atributos) e comportamento (métodos).            | Alta reutilização de código (ex: herança), excelente organização e fácil manutenção. | Execução ligeiramente menos eficiente devido ao nível de abstração.          | Java, C++, C#      |

## 💻 Exemplos de Código

**Paradigma Orientado a Objetos (Java):** Uma classe define o estado e os métodos do objeto.
```java
public class Carro {
    private String cor;
    private double velocidade;

    public void Acelerar() {
        velocidade += 10;
    }
}
```

**Paradigma Funcional (Haskell):** Solução puramente matemática (cálculo de distância), sem atribuição de variáveis dinâmicas.
```haskell
dist x1 y1 x2 y2 = sqrt(((x2 - x1)^2) + ((y2 - y1)^2))
```

## 🎯 Conclusão
Não existe um paradigma ou linguagem universalmente superior. A eficiência do desenvolvimento de software exige adequar a ferramenta ao domínio do problema. Aplicações que lidam com hardware crítico favorecem o paradigma imperativo de baixo/médio nível, enquanto sistemas comerciais modernos em grande escala dependem quase exclusivamente do paradigma Orientado a Objetos e de linguagens de alto nível para garantir facilidade de manutenção e trabalho em equipe.
